# Identify the query language in the plugin with a langid-32 character n-gram model, to choose which glossary terms the keyword boost looks up

langid-32 (github.com/SylvainSouche/langid-32): 34 labels covering all 21 languages of the evaluation's language matrix. In the plugin only a pure Python + numpy model of a few MB fits, so the n-gram variant; the byte-level transformer does not. Requirements: probabilities rather than one label (nb/nn/da/sv, es/ca/pt, sk/cs/sl/hr are close on 3 words), abstention when unsure, short inputs (1-3 word keywords, 5-10 word sentences), shared GIS words (raster, DEM, WMS) ignored, QGIS interface locale as prior. Glossary matches carry their own language evidence, so langid mainly settles ambiguous words. Test on Queries.json (40 needs x 21 languages, sentences and 1-3 word fragments) and the native needs; these never enter langid training. A shipped model may only use training text cleared in langid-32's source register.
